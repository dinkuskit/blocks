# Feature ownership map

This map is the repository contract for bounded feature work. A feature owns its listed implementation paths and reaches another feature only through that feature's public entry. Repository-level consumers use the package root or `@dinkuskit/blocks/astro`; they do not import feature internals. Shared dependencies are explicit and narrow.

CTA Band, Page Hero, Section Header, Fact Rail, and Gallery Hero are the feature-local pilots. The remaining six blocks stay mapped at their current paths until a later confirmed cycle migrates one of them. A structural migration must preserve the public compatibility surface named here and follow `COMPAT.md`.

## Boundary rules

- A feature may import its own files, declared shared modules, third-party packages, and another feature's `index.ts` only.
- Files outside a feature may reach that feature only through its `index.ts`; the package's `src/astro/index.ts` adapter alone may wire the feature's `renderer.astro` into `@dinkuskit/blocks/astro`.
- Tests and fixture consumers reach publishable code through `@dinkuskit/blocks`, `@dinkuskit/blocks/astro`, `src/index.ts`, or `src/astro/index.ts`.
- Durable rationale belongs in this contract, architecture documentation, compatibility documentation, tests, or issue references rather than source comments.
- `scripts/check-architecture.mjs all` validates this table, import boundaries, and the governed-file comment policy.

The feature grain is the reusable block responsibility, not a folder-name template for other repositories. Portfolio repositories adapt these ownership and verification concepts to their own domain grains.
