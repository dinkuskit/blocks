# EmDash 0.40.1 compatibility baseline

Date: 2026-09-25
Base: `origin/main` `c33fb51` (merged PR #49)

## Decision

DinkusKit Blocks now targets exact `emdash@0.40.1` and
`@emdash-cms/blocks@0.40.1` in its package, peer, and fixture contracts. The
pin is exact while EmDash is pre-1.0. It does not widen the supported range,
add a first-class `blocks` field, or authorize publication, marketplace
listing, deployment, or production mutation.

`emdash@0.40.0` added first-class `blocks` fields and said a site older than
0.39 must deploy 0.39 before creating one. This package does not create that
field. Stored Dinkus block types, field arrays, and renderers are unchanged.
Relations from emdash-cms/emdash#1928 are not in this release.

## Observed 0.40.1 admin change

The pending-change action is labeled `Publish changes` again. Clicking it
opens a confirmation dialog, `Publish changes?`, whose confirm button has the
same name. The acceptance tests confirm that dialog and then wait for
`Unpublish`. No stored field, block type, export, renderer hook, class, theme
token, or public SSR contract changed.

## Verification

- `pnpm install` resolved `emdash@0.40.1` and `@emdash-cms/blocks@0.40.1`.
  pnpm's release-age gate required `minimumReleaseAgeExclude` entries for
  those packages and their same-version admin, auth, and portable-text
  dependencies.
- `bin/verify-blocks` `check` passed before the selector change: architecture,
  TypeScript, 29 unit tests, 11 workflow tests, the fixture build, and the
  package-content check.
- `DINKUS_E2E_RUN_ID=emdash-0401-confirm-1790370282 pnpm test:e2e` passed all
  12 Chromium scenarios in 3.3 minutes. Each scenario covers declaration,
  edit, insertion, persistence, publication, and public SSR.

The fixture build retains the existing large-chunk warning. It is
non-blocking and does not change this exact-version compatibility verdict.
