# EmDash 0.35 compatibility baseline

Date: 2026-08-27  
Base: `fcd539aa08fbce708761361832e4ff12fd33a761`

## Decision

DinkusKit Blocks now targets exact `emdash@0.35.0` and
`@emdash-cms/blocks@0.35.0` in its package, peer, and fixture contracts. The
pin is intentionally exact while EmDash is pre-1.0. It does not widen the
supported range or authorize publication, marketplace listing, deployment, or
production mutation.

The lock keeps the existing TipTap `3.28.0` cohort coherent by constraining the
new subscript and superscript extensions to that same version. This removes a
mixed-version peer graph without changing DinkusKit's public package surface.

## Observed 0.35 migrations

- The pending-change admin action is now exposed as `Publish`; acceptance tests
  no longer look for the prior `Publish changes` label.
- The modal-submit race previously tracked as an expected failure against
  EmDash `0.29.0` did not reproduce. The canary is now an ordinary regression
  that requires zero competing manual saves and the edited value after reload.
- No stored field, block type, export, renderer hook, class, theme token, or
  public SSR contract changed.

## Verification

- `pnpm peers check` — no peer dependency issues.
- `pnpm check` — TypeScript and Astro diagnostics clean; 28 unit tests and 11
  workflow tests passed; fixture build and package-content checks passed.
- `DINKUS_E2E_RUN_ID=emdash-035-final pnpm test:e2e` — all 12 serial Chromium
  scenarios passed, covering declaration, edit, insertion, persistence,
  publication, and public SSR across every shipped block shape.

The fixture build retains the existing large-chunk warning. It is non-blocking
and does not change this exact-version compatibility verdict.
